# DeepSeek Harness Desktop

[English](README.md) · **Русский**

Десктопный клиент для уже запущенного DeepSeek Harness. Он открывает веб-интерфейс
сервера в собственном окне и добавляет нативные меню macOS/Linux/Windows.
Оболочка закреплена по размеру окна: прокручиваются сообщения и списки внутри
панелей, а весь интерфейс остаётся на месте.

## Подключение

1. Запустите контейнер DeepSeek Harness и опубликуйте его веб-порт на хосте.
2. Откройте приложение и вставьте адрес, например `localhost:3000`.
3. Если сервер требует авторизацию, вставьте полную ссылку с `?token=…`, которую
   он выдал при запуске. Нажмите **Подключиться**.

При следующем запуске приложение предложит последний адрес. Query-параметры и
фрагмент URL не сохраняются; cookie авторизации остаются в профиле WebView.
После истечения сессии понадобится новая полная ссылка. Ссылка для браузера на хосте
может отличаться от адреса внутри контейнера. `localhost` и `127.0.0.1` — разные
адреса для авторизации: сохраняйте имя хоста из выданной сервером ссылки.

В меню **Файл** можно сменить сервер (`Cmd/Ctrl+L`) или сбросить сохранённую
браузерную сессию. **Вид → Перезагрузить** (`Cmd/Ctrl+R`) обновляет интерфейс.
На macOS закрытие окна оставляет приложение в Dock; **Окно → Показать окно** или
нажатие на Dock возвращает его. На Linux и Windows закрытие основного окна завершает
приложение. На Windows полноэкранный режим переключается через **Вид** или F11.

## Язык приложения

Доступны English и Русский. По умолчанию выбран **Язык системы**: русский язык
системы включает русский интерфейс, английский — английский. Для других языков
системы используется английский. Региональные варианты, например `ru-RU` и `en-GB`,
также распознаются.

Откройте **Настройки…** в меню приложения (`Cmd/Ctrl+,`) или кнопкой на экране
подключения. Выберите **Язык системы**, **English** или **Русский**. Изменения
применяются сразу и сохраняются после перезапуска; подключение к серверу остаётся
активным. Настройка переводит экран подключения, настройки, меню, сообщения об
ошибках и диалоги клиента. Язык серверного веб-интерфейса задаётся в самом Harness.

## Разработка

Требуются npm и Node.js из `.node-version`; Rust с Clippy/rustfmt закреплён в
`rust-toolchain.toml` и устанавливается через rustup. На macOS нужны
Command Line Tools (`xcode-select --install`); целевая платформа macOS 14+, Apple Silicon.
Rust, установленный локально в `.tools`, автоматически подхватывается скриптами;
в обычной установке используется системный `cargo`.

```sh
npm ci
npm run desktop:dev
```

Для Linux нужны WebKitGTK 4.1 и нативные инструменты из
[официального списка Tauri](https://v2.tauri.app/start/prerequisites/).
Базовая среда — Ubuntu 22.04/Debian 12, x86_64.

Для Windows 10/11 x64 установите Visual Studio Build Tools с компонентом
**Desktop development with C++**, rustup с toolchain `x86_64-pc-windows-msvc`
и Microsoft Edge WebView2 Runtime. Для MSI нужен включённый компонент VBScript.
Требования описаны в [документации Tauri](https://v2.tauri.app/start/prerequisites/).
Команды `npm ci`, `desktop:dev`, `check` и `native:check` работают из PowerShell
без Bash. Для `fixture` и `ci:check` также нужен Python 3.9+ в PATH.

```sh
npm run check
npm run native:check
npm run audit
npm run desktop:build
```

Сборки macOS `.app`/`.dmg`, Linux `.deb`/`.AppImage` и Windows `.exe`/`.msi` находятся в
`src-tauri/target/release/bundle/`. Первая версия предназначена для локального
использования; для macOS настроена ad-hoc подпись. Apple Developer ID, notarization
и автоматическое обновление не настроены.
Windows-пакеты пока без Authenticode-подписи.
Готовые пакеты и диагностические файлы создаются локально или в GitHub Actions;
в Git они не включаются.

Исходник иконки — `assets/app-icon.svg`; `npm run icons` пересоздаёт PNG, ICNS и ICO.
Закреплённый источник контура DeepSeek указан в [SVG](assets/app-icon.svg),
лицензия сохранена в [LICENSE-deepseek](assets/LICENSE-deepseek).

### Linux-сборка в Docker на Mac

```sh
npm run linux:build
```

Команда выполняет проверки Rust/frontend, тест GTK-диалога, проверку установленного
DEB в Xvfb, проверку языков/настроек и запуск упакованного AppRun из извлечённого
AppImage. Готовые пакеты, SHA-256 и снимки WebView сохраняются в
`artifacts/linux/`. Исходники копируются в образ,
инструменты macOS туда не попадают. Эмуляция x86_64 на Apple Silicon замедляет сборку.
Для несовместимого с эмуляцией загрузчика инструмента AppImage предусмотрен запуск
того же официального плагина из распакованного AppDir; его SHA-256 закреплён в скрипте.

На Linux DEB устанавливается через `sudo apt install ./имя-пакета.deb`. Для AppImage
выдайте право выполнения (`chmod +x файл.AppImage`) и запустите файл. При отсутствии
FUSE используйте `файл.AppImage --appimage-extract-and-run`.

### Windows-сборка и установка

На Windows выполните `npm ci`, затем `npm run windows:build`. Команда собирает
NSIS `.exe` и WiX `.msi`, проверяет архитектуру/версию пакетов и сохраняет их с
SHA-256 в `artifacts/release-windows-x86_64/`. Для подготовки metadata нужен Python.
Повторная сборка требует переместить предыдущий каталог артефактов.

Рекомендуемый установщик `*-setup.exe` устанавливает приложение для текущего
пользователя и предлагает English/Русский. MSI использует английский интерфейс
установки и может требовать права администратора. Язык самого приложения в обоих
случаях следует системе или настройке пользователя.

Установщики включают bootstrapper WebView2. Если runtime отсутствует или слишком
старый, для его установки требуется интернет. Готовый файл можно скачать из
Artifacts успешного Windows job или общего GitHub Release; Windows может показать
предупреждение о неизвестном издателе, поскольку подпись пока не настроена.

## GitHub Actions

CI проверяет PR и коммиты, собирает macOS arm64 (`.app`/`.dmg`), Linux x86_64
(`.deb`/`.AppImage`) и Windows x64 (`.exe`/`.msi`), сохраняет пакеты, SHA-256 и
диагностику. Push тега `v<версия>`
запускает те же проверки и создаёт **черновик** релиза. Дополнительные secrets
для текущих сборок не нужны.

Настройка репозитория, обязательная проверка `CI required`, подготовка версии и
публикация: [docs/github-actions.md](docs/github-actions.md).

## Проверка авторизации и нативного поведения

`npm run fixture` запускает локальный тестовый сервер на порту 4317. Его публичная
тестовая ссылка: `http://localhost:4317/?token=fixture-token`. Сервер воспроизводит
303 → HttpOnly/SameSite=Strict cookie → защищённые API/WebSocket; страница содержит
проверку IPC, выбор файла, скачивание, внешний URL и истечение cookie.
Для проверки закреплённой оболочки используйте
`http://localhost:4317/shell?token=fixture-token`: длинные списки и код прокручиваются
независимо; заголовок и поле ввода остаются видимыми. Эта страница также проверяет
отложенное появление корневого блока и строгую CSP сервера.

Матрица проверки и фактические результаты: [docs/verification.md](docs/verification.md).
Границы доверия и поведение окон: [docs/architecture.md](docs/architecture.md).
Внешний веб-клиент не получает доступ к Rust-командам, файлам или запуску процессов.
Сертификаты HTTPS проверяются; для собственного CA настройте доверие ОС.

Авторизация соответствует [механизму DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/connection/README.md).
